## 1. Введение и фундаментальный принцип дельта-нейтральности

Арбитраж ставок финансирования (Funding Rate Arbitrage) — это класс **рыночно-нейтральных (дельта-нейтральных)** стратегий. В отличие от направленных спекуляций, финансовый результат стратегии не зависит от того, растет базовый актив, падает или находится в боковике.

### 1.1. Математический инвариант дельты
Для связки из двух противоположных позиций (нога 1 на площадке $A$ и нога 2 на площадке $B$) суммарная дельта позиции обязана стремиться к нулю:
$$\Delta_{total} = \text{Notional}_A \cdot \delta_A + \text{Notional}_B \cdot \delta_B \approx 0$$
где:
* $\text{Notional}$ — долларовый объем позиции ($\text{Price} \times \text{Quantity}$);
* $\delta_A = +1.0$ (для Long позиции) и $\delta_B = -1.0$ (для Short позиции).

Если цена актива меняется на величину $\Delta P$:
$$\text{PnL}_{price} = \text{Notional}_A \cdot \frac{\Delta P_A}{P_A} - \text{Notional}_B \cdot \frac{\Delta P_B}{P_B} \approx 0$$
Поскольку обе ноги завязаны на один и тот же базовый актив (либо синтетический аналог), движение цены взаимно аннигилируется.

### 1.2. Формула чистой прибыли (Net Edge)
Доход генерируется из структурных выплат, а чистая прибыль за период удержания $T$ вычисляется как:
$$\text{Net PnL} = \sum \text{Funding Earned} - \sum \text{Funding Paid} - \text{Commissions}_{entry/exit} - \text{Overnight Costs} \pm \Delta\text{Spread}_{entry \to exit} - \text{Slippage}$$

### 1.3. Строгая двунаправленность (Long & Short)
Стратегия всегда двунаправленна:
* **Если ставка на CEX положительна ($Funding > 0$)**: розничная толпа перегружена в лонгах.  
  $\implies$ **SHORT на CEX** (получаем фандинг) + **LONG на хеджирующей площадке** (хеджируем рост цены).
* **Если ставка на CEX отрицательна ($Funding < 0$)**: рынок в паническом сбросе, шортисты платят огромную премию.  
  $\implies$ **LONG на CEX** (получаем фандинг от шортов) + **SHORT на хеджирующей площадке** (хеджируем падение).

## 2. Общий фундамент: Протоколы двух ног (Shared Core Protocols)

Главная инженерная проблема любого арбитража между двумя независимыми биржами — **отсутствие распределенной транзакции (ACID Two-Phase Commit)**. В публичных API бирж нельзя выполнить один сетевой вызов, который гарантированно и атомарно откроет обе ноги на разных серверах в одну и ту же наносекунду.

Ниже описаны строгие правила и протоколы, общие для обоих под-проектов.

---

### 2.1. Протокол одновременного входа: Как обеим ногам встать на землю одновременно?

```
                       ┌──────────────────────────────┐
                       │     СИГНАЛ НА ВХОД В СВЯЗКУ   │
                       └──────────────┬───────────────┘
                                      │
                                      ▼
               ┌──────────────────────────────────────────────┐
               │    ФАЗА 1: ИСПОЛНЕНИЕ НА СЛОЖНОЙ НОГЕ        │
               │  (Менее ликвидная / Тонкая / UTEX / Мейкер)  │
               └──────────────────────┬───────────────────────┘
                                      │
                      ┌───────────────┴───────────────┐
                      ▼                               ▼
                 [УСПЕХ / FILL]                 [ОТКАЗ / TIMEOUT]
                      │                               │
                      ▼                               ▼
       ┌──────────────────────────────┐    ┌────────────────────┐
       │   ФАЗА 2: МОМЕНТАЛЬНЫЙ ХЕДЖ  │    │   ОТМЕНА СВЯЗКИ    │
       │   (Глубокий CEX / Binance)   │    │  (Дельта = 0,      │
       │     IOC / Market / Taker     │    │   убыток = $0)     │
       └──────────────┬───────────────┘    └────────────────────┘
                      │
              ┌───────┴───────┐
              ▼               ▼

              │               │
              ▼               ▼
      ┌──────────────┐ ┌──────────────────────┐
      │ СВЯЗКА В СТРОЮ│ │ ПРОТОКОЛ СБОЯ (2.2)  │
      │  Δ_net = 0   │ │ Выравнивание дельты  │
      └──────────────┘ └──────────────────────┘
```

#### Правило №1: Асимметрия ликвидности (The Liquidity Rule: Who Leads?)
> **Золотое правило арбитража**: Первой ВСЕГДА исполняется **менее ликвидная, медленная или рестриктивная нога (Illiquid / Restricted Leg)**. Вторая нога на высоколиквидном рынке исполняется строго как **мгновенный хедж (Instant Hedge)**.

* **Почему нельзя делать наоборот**:  
  Если сначала открыть ногу на сверхликвидном Binance, а затем послать ордер на тонкую площадку (UTEX или сонный альткоин MEXC/Gate), в стакане второй биржи может не оказаться нужного объема, либо сервер вернет ошибку. Трейдер окажется с **голым направленным риском (Naked Directional Risk)** на волатильном рынке Binance!
* **Как правильно**:  
  Сначала забирается объем (или выставляется лимит) на менее ликвидной площадке. Как только получен отчет о наливке (`Fill Event`), сокет за $5\dots 15$ мс наносит встречный удар по глубокому стакану Binance/Bitget, где исполнение гарантировано на $100\%$.

#### Правило №2: Типы защитных ордеров (IOC / FOK)
* Для второй (хеджирующей) ноги запрещено использовать обычные пассивные лимиты, которые могут остаться стоять в стакане без исполнения.
* Используются типы:
  * **`IOC` (Immediate-Or-Cancel)**: мгновенно забрать доступный объем по цене не хуже лимитной, а весь неисполненный остаток немедленно отменить.
  * **`FOK` (Fill-Or-Kill)**: исполнить заявленный объем целиком и немедленно, либо не исполнять вовсе.
  * **Market Order с защитным проскальзыванием (Slippage Cap)**: удар по рынку с лимитом цены не более чем на $+0.10\dots +0.15\%$ от текущего беста.

#### Правило №3: Порционное квантование объема (Chunking / Slicing)
* Позиция крупного объема (например, $\$50\,000$) никогда не бросается в рынок целиком.
* Алгоритм нарезает ее на порции (микро-чанки) по $\$3\,000 \dots \$10\,000$:
  $$\text{Chunk}_1 \to \text{Fill 1} \to \text{Hedge 1} \implies \text{Chunk}_2 \to \text{Fill 2} \to \text{Hedge 2} \implies \dots$$
* Если на очередном шаге рынок дернулся или ликвидность иссякла — незахеджированный риск составит всего один микро-чанк ($\$3\,000$), а не весь депозит ($\$50\,000$).

### 2.2. Протокол обработки сбоя исполнения: Что делать, если нога зависла в воздухе?

Если произошел технический сбой, сетевой тайм-аут или резкий уход котировок, и связка разорвалась, включается **Leg Failure Protocol**.

#### Сценарий А: Нога 1 исполнилась, Нога 2 отклонена (Reject / Network Disconnect)
* **Проблема**: образовалась 100% направленная позиция на Ноге 1.
* **Реакция (Emergency Unwind / Flattening)**:
  1. Таймер ожидания подтверждения второй ноги: $T_{max} = 300\dots 500$ мс.
  2. Если за 500 мс от второй биржи нет подтверждения исполнения — **включается аварийный стоп-кран (Kill-Switch)**.
  3. Алгоритм немедленно сбрасывает Ногу 1 встречным рыночным ордером (Unwind).
  4. Мы принимаем микро-убыток на спреде и комиссии как плату за страховку. Направленный риск ликвидируется мгновенно.

#### Сценарий Б: Частичное исполнение (Partial Fill Asymmetry)
* **Проблема**: на Ноге 1 куплено 1000 контрактов ($\$10\,000$), а на Ноге 2 из-за нехватки ликвидности продалось только 400 контрактов ($\$4\,000$).
* **Дисбаланс дельты**: $+600$ контрактов ($\$6\,000$) висят без хеджа.
* **Реакция (Delta Equalization)**:
  1. Алгоритм не пытается любой ценой добрать недостающие 600 контрактов на Ноге 2 по грабительским ценам.
  2. Алгоритм **приводит Ногу 1 к размеру Ноги 2**: сбрасывает в рынок избыточные 600 контрактов на Ноге 1.
  3. Итог: остается идеально сбалансированная дельта-нейтральная связка на 400 контрактов ($\$4\,000$), а чистая дельта снова равна нулю ($\Delta_{total} = 0$).

#### Сценарий В: Превышение порога проскальзывания (Slippage Cap Exceeded)
* Если во время отправки второй ноги цена перпа ушла более чем на `max_slippage_bps` (например $> 15$ bps):
  1. Ордер второй ноги отменяется.
  2. Первая нога сбрасывается обратно в рынок.
  3. Трейд помечается статусом `ABORTED_SLIPPAGE`.

### 2.3. Протокол синхронного выхода и балансировка маржи

#### Синхронный выход (Exit Unwind)
1. Выход из связки повторяет логику входа в обратном порядке:
   * Сначала закрывается нога на менее ликвидной площадке.
   * Получив подтверждение закрытия, алгоритм мгновенно закрывает ногу на ликвидной площадке.
2. При частичном закрытии одной ноги вторая нога зеркально уменьшается до того же размера.

#### Распределение капитала и буфер ликвидации (50/50 Margin Allocation)
* **Критический риск новичка**: держать $\$10\,000$ на площадке $A$ (1x плечо) и всего $\$500$ на площадке $B$ (с плечом $20\times$). При резком движении площадка $B$ ликвидируется по маржин-коллу, оставляя трейдера с голым убыточным лонгом на площадке $A$.
* **Правило**:
  * Капитал распределяется строго **50% на 50%** между счетами.
  * Плечо выбирается консервативным: для крипты $2\times \dots 3\times$, для TradFi/акций строго $1\times$ (без плеча).
  * На криптобиржах используется строго **Isolated Margin** (изолированная маржа).

### 2.4. Протокол микроструктурного сайзинга объема: Как не сдвинуть стакан слабой ноги? (OrderBook Sizer & Stealth POV)

Главная ошибка новичка при арбитраже на тонких альтах или неликвидных площадках (UTEX, Aster DEX, MEXC, BingX) — войти рыночным ордером на весь депозит. Рыночный ордер сметает уровни в стакане, вызывая катастрофическое проскальзывание (Market Impact), которое мгновенно уничтожает весь спред фандинга.

Для защиты от сдвига стакана в системе реализован институциональный протокол **Stealth POV (Percentage of Volume at Top-of-Book)**.

#### 1. Принцип «Узкого горлышка» (Bottleneck Leg Principle)
Перед выставлением ордера алгоритм сканирует сторону стакана, по которой будет совершаться вход:
* Для Long-ноги: первые 3 уровня **Asks** (предложение на продажу).
* Для Short-ноги: первые 3 уровня **Bids** (спрос на покупку).
* Суммируется долларовый объем:
  $$L_{\text{long}} = \sum_{i=1}^3 P_i \times Q_i, \quad L_{\text{short}} = \sum_{i=1}^3 P_i \times Q_i$$
* **Слабой ногой** признается нога с минимальной доступной ликвидностью:
  $$L_{\text{weak}} = \min(L_{\text{long}}, L_{\text{short}})$$
* Размер входа на **обеих биржах** строго ограничен емкостью слабой ноги!

#### 2. Правило 10% от первых трех уровней (The 10% Rule)
* Объем разового безопасного входа ($V_{\text{opt}}$) рассчитывается как:
  $$V_{\text{opt}} = \alpha \times L_{\text{weak}}, \quad \alpha = 0.10 \text{ (10\%)}$$
* **Почему именно 10%?**
  * Алгоритмические маркет-мейкеры (ММ) на биржах непрерывно котируют стакан. Если забрать $\le 10\%$ от видимых объемов, для ММ это выглядит как обычный шум розничной торговли. ММ восстанавливают стакан за $100\dots 500$ мс без сдвига средней цены (Midpoint).
  * Если забрать $> 25\dots 50\%$ стакана, сработают защитные триггеры ММ: они снимут остальные котировки и расширят спред в 3–5 раз, вызвав проскальзывание в $0.3\dots 1.5\%$.
* При заборе $10\%$ расчетный сдвиг цены (VWAP Slippage) составляет всего **$0.5 \dots 2.0$ bps ($0.005\% \dots 0.020\%$)**, что сохраняет $99\%$ расчетного дохода со спреда.

#### 3. Фильтр разрывов и «дыр» в стакане (Gap & Hole Filter)
* Перед суммированием проверяется шаг цены между соседними уровнями стакана.
* Если шаг цены превышает `max_level_slippage_bps` (15 bps / 0.15%), стакан считается разорванным. Дальнейшие уровни отсекаются, чтобы не учитывать иллюзорную ликвидность на глубине.

#### 4. Защитная отбраковка «бумажного стакана» (Paper-Thin Book Rejection)
* Если расчетный безопасный объем $V_{\text{opt}} < \text{min\_notional\_usdt}$ ($\$10$ USDT):
  * **Вход полностью блокируется (`is_tradable = False`)!**
  * Если на слабой бирже во всех 3 уровнях лежит суммарно всего $\$50$, заходить даже на $\$10$ нельзя — этот вход сожрет $20\%$ книги и толкнет рынок против нас.

#### 5. Протокол накопления крупной позиции (Chunked Iceberg Protocol)
Для крупного капитала (наследие практики Сергея и Антона на UTEX):
* Если целевой объем позиции в привлекательной монете составляет $\$2\,000 \dots \$10\,000$, а безопасный разовый слайс равен, например, $\$400$:
* Алгоритм **не бросает крупный ордер в стакан**.
* Позиция накапливается **дробными слайсами (Chunks)**:
  * Вход слайсом $\$400$ на слабой ноге $\to$ мгновенный хедж $\$400$ на ликвидной ноге.
  * Пауза в $30\dots 60$ секунд (время, необходимое маркет-мейкерам для полного восстановления первых 3 слоев стакана).
  * Вход следующим слайсом $\$400$.
  * Повторение до набора целевого объема позиции с полным отсутствием рыночного импакта.

## 3. Под-проект 1: Межбиржевой крипто-фандинг (Crypto-to-Crypto Funding Arbitrage) — [ПРИОРИТЕТ №1]

### 3.1. Торговое окружение и полный пул бирж (Full Exchange Universe)
* **Площадки (полный охват без урезания)**:
  * Tier 1 CEX: **Binance Futures**, **Bybit Linear**, **OKX Swap**, **Bitget Futures**.
  * Альткоин-гиганты: **MEXC Futures**, **Gate.io Futures**, **BingX Swap**, **KuCoin Futures**, **HTX Futures**.
  * On-Chain Perp DEX: **Hyperliquid DEX** (L1 Perp с нулевыми комиссиями для мейкера).
  * *Все 10 бирж интегрированы в коннектор `CCXTConnector` и поддерживаются без исключений*.
* **Режим работы**: **24/7/365** без выходных, праздников и пауз.
* **Специфика соединения**: высокоскоростные WebSockets (ccxt.pro) с подтверждением тиков за 5–50 мс, прямое чтение стаканов L2 Depth.
* **Расписание выплат**: синхронное на всех площадках — каждые 8 часов в **00:00, 08:00, 16:00 UTC**.

### 3.2. Стратегическая суть
Поиск монет с сильным расхождением ставок между двумя криптобиржами:
$$\Delta\text{Rate}_{8h} = \text{Rate}_{\text{CEX}_1} - \text{Rate}_{\text{CEX}_2} \ge \Delta_{\text{optimal}}$$
* На бирже с высокой ставкой открывается **Short** (получаем фандинг от лонгов).
* На бирже с низкой/отрицательной ставкой открывается **Long** (получаем фандинг или платим минимум, хеджируя спотовое движение цены).

### 3.3. Научное и эмпирическое обоснование порога входа (Почему именно 0.08% — 0.10%?)

Порог $\Delta_{\text{Funding}}$ не взят с потолка. Он математически выведен из структуры трения и эмпирически подтвержден на выборке из **5,112 сигналов за 28.6 дней** (`data/scanner.db`).

#### 1. Модель совокупных издержек (Friction Cost):
* Комиссия тейкера: $0.05\%$ за сделку $\times 4$ сделки (вход Long+Short, выход Long+Short) $= 0.20\%$ ($20\text{ bps}$).
* Проскальзывание и пересечение спреда стакана (Slippage): $\approx 0.04\%$ ($4\text{ bps}$) на круг.
* **Итого издержки на круг**: $C_{\text{friction}} = 0.20\% + 0.04\% = 0.24\%$ ($24\text{ bps}$).

#### 2. Математическое уравнение безубыточности (Breakeven Formula):
Для удержания позиции в течение $k$ периодов по 8 часов:
$$k \cdot \Delta F \ge C_{\text{friction}} \implies \Delta F_{\text{breakeven}} = \frac{0.24\%}{k}$$

* **При удержании 1 период (8 часов, $k=1$)**:
  $$\Delta F_{\text{breakeven}} = \frac{0.24\%}{1} = \mathbf{0.24\%} \text{ за 8ч}$$
  *(Входить ради одной выплаты при $\Delta < 0.24\%$ — гарантированный убыток!)*
* **При удержании 2 периода (16 часов, $k=2$)**:
  $$\Delta F_{\text{breakeven}} = \frac{0.24\%}{2} = \mathbf{0.12\%} \text{ за 8ч}$$
* **При удержании 3 периода (24 часа / 1 сутки, $k=3$)**:
  $$\Delta F_{\text{breakeven}} = \frac{0.24\%}{3} = \mathbf{0.080\%} \text{ за 8ч!}$$
  **Вот точная математическая причина значения 0.08%**: 3 начисления по $0.08\%$ дают $+0.24\%$ валового дохода, что в ноль окупает $0.20\%$ комиссий тейкера и $0.04\%$ спреда!
* **При удержании 9 периодов (72 часа / 3 суток, $k=9$)**:
  $$\Delta F_{\text{breakeven}} = \frac{0.24\%}{9} = \mathbf{0.027\%} \text{ за 8ч}$$

### 3.4. Динамическое удержание и фактические сигналы на выход (Dynamic Exit Protocol)

Искусственное закрытие позиции ровно через «72 часа» при условии, что связка продолжает стабильно приносить $+0.15\dots +0.30\%$ каждые 8 часов — **экономически нецелесообразно**, так как влечет лишние комиссии за закрытие ($0.20\%$) и недополученную прибыль.

В системе реализовано **динамическое удержание («Dripping until Decay»)**: позиция удерживается **до тех пор, пока рынок щедро платит**, и закрывается строго по факту рыночных событий.

#### Фактические триггеры выхода:
1. **Инверсия ставки (Rate Inversion — экстренный выход)**:
   * $\Delta\text{Rate}_{8h} \le 0.0\%$.
   * *Физика*: сентимент рынка развернулся, и вместо получения фандинга мы начинаем платить чужой стороне. Позиция закрывается немедленно.
2. **Затухание ставки (Funding Decay — экономический выход)**:
   * $\Delta\text{Rate}_{8h} < 0.02\%$ (спред упал ниже порога поддержания позиции).
   * *Физика*: арбитражеры стянули цены, толпа остыла. Денежный поток иссяк — капитал освобождается для новых связок с $\Delta \ge 0.10\%$.
3. **Защитный стоп-лосс по расхождению цен (Spread Stop — риск-менеджмент)**:
   * Относительный спред спот-цен между биржами расширился на $|\Delta\text{Spread}| > 2.0\%$ от точки входа.
   * *Физика*: локальный раскорреляционный сквиз, угроза делистинга или технический сбой одной из бирж. Немедленная ликвидация риска.
4. **Аварийный предохранитель по времени (Safety Timeout)**:
   * Удержание до 14 дней (336 часов) — защита от вечно висящих «спящих» позиций. Полноценная замена жесткому лимиту в 72 часа.

### 3.7. Графа «Спот — Фьючерс»: Стратегия Cash & Carry (Спот Uniswap Long + Перп CEX/DEX Short)

Стратегия «Спот — Фьючерс» (Cash & Carry) выделена в системе в **отдельную независимую торговую графу**. В отличие от классического кросс-перп арбитража (`Perp Long` $\longleftrightarrow$ `Perp Short`), здесь одна из ног является **реальным ончейн-спотом**.

```

                        │        КВАЛИФИЦИРОВАННЫЙ СИГНАЛ CASH & CARRY           │
                        │    (Ставка фандинга на CEX/DEX F >= +0.10% за 8ч)      │
                        └──────────────────────────┬─────────────────────────────┘
                                                   │
                         ┌─────────────────────────┴─────────────────────────┐
                         ▼                                                   ▼
            [ НОГА 1: СПОТ UNISWAP V3 ]                         [ НОГА 2: ПЕРП CEX / D-DEX ]
               ПОКУПКА ТОКЕНА (LONG)                               ОТКРЫТИЕ ШОРТА (SHORT)
            • Без плеча (1x Spot)                               • С плечом 2x..3x (Isolated)
            • 0% риск ликвидации (ончейн)                       • Получает фандинг F каждые 8ч
            • 0% плата за маржу / заем                          • Полный дельта-хедж спота
            • Swap fee: 0.05% или 0.30%                         • Taker fee: 0.05%

                                                   ▼

                                │     ДЕЛЬТА-НЕЙТРАЛЬНЫЙ ПОРТФЕЛЬ      │
                                │   • Δ_total = 0.0 (риск цены = 0)    │
                                │   • Доход = +F каждые 8 часов        │
                                └──────────────────────────────────────┘
```

#### 1. Фундаментальные преимущества графы «Спот — Фьючерс»:
1. **Физическая неуязвимость спотовой ноги (Zero Liquidation Risk)**:
   * Реальный токен лежит на некастодиальном ончейн-кошельке алгоритма. Даже при падении рынка на $90\%$ спотовая нога **никогда не ликвидируется**.
   * Риск ликвидации контролируется исключительно на фьючерсной шорт-ноге (поддерживается плечо $\le 3\times$ с запасом маржи $>33\%$).
2. **Нулевая стоимость заимствования (0% Borrow Cost)**:
   * При маржинальном споте на CEX трейдер обязан платить почасовую ставку за заем USDT или базового актива ($5\dots 15\%$ годовых). На Uniswap спот выкупается за собственный стейблкоин, стоимость удержания равна строго **$0.00$**.
3. **Отсутствие зависимости от спреда ставок двух бирж**:
   * Достаточно, чтобы **всего одна биржа** (например, Bybit или Aster DEX) имела перегретую ставку фандинга ($F \ge +0.10\%$).

#### 5. Резюме и операционный регламент Cash & Carry:
1. **Порядок открытия**:
   * **Шаг 1**: Покупка токена на Uniswap v3 через L2-роутер (слабая/медленная ончейн-нога выставляется первой).

2. **Порог входа**:
   * Для токенов с пулом $0.05\%$: вход при $F \ge \mathbf{0.10\%}$ (окупаемость за 16 часов).
   * Для токенов с пулом $0.30\%$: вход при $F \ge \mathbf{0.15\%}$ (окупаемость за 48 часов) с удержанием не менее 3 суток.
3. **Выход из позиции**:
   * При затухании ставки $F < 0.02\%$ или при уходе ставки в минус ($F \le 0\%$).
   * Закрытие шорта на CEX/DEX $\to$ продажа спота на Uniswap обратно в USDC/USDT.

## 4. Под-проект 2: TradFi-арбитраж фандинга (UTEX CME & US Stocks $\longleftrightarrow$ CEX)

### 4.1. Торговое окружение и инфраструктура
* **Площадки**: брокер UTEX (реальные фьючерсы CME и акции США за USDT) $\longleftrightarrow$ Binance / Bitget Futures (TradFi бессрочные контракты).
* **Инструменты**:
  * *Сырье и металлы*: Природный газ (`GASM` / `NATGASUSDT`), Нефть WTI (`CL` / `CLUSDT`), Золото (`XAU` / `XAUUSDT`).
  * *Акции США*: Nokia (`NOK` / `NOKUSDT`), AXT Inc (`AXTI` / `AXTIUSDT`), MicroStrategy (`MSTR` / `MSTRUSDT`), Tesla (`TSLA` / `TSLAUSDT`).
* **Депозит**: 100% в стейблкоинах USDT на обеих площадках. Никаких валютных переводов, банков и счетов в Interactive Brokers.

### 4.2. Главные структурные особенности и правила UTEX

#### Особенность 1: Несовпадение торговых часов (Market Hours Gap)
* Binance торгует 24/7/365.
* UTEX работает по расписанию традиционных бирж:
  * Акции (NYSE/NASDAQ): 13:30 – 20:00 UTC (плюс пре-/постмаркет). Вне сессии торги закрыты.
  * CME фьючерсы: имеют ежедневный часовой клиринговый перерыв и закрываются на выходные (с вечера пятницы до ночи воскресенья).
* **Правило риска**:
  * В нерабочие часы UTEX позиция становится временно «одноногой» (крипто-нога реагирует на новости, а UTEX заморожен до утра).
  * *Защита*: **Строго 1:1 без плеча** на акциях! Никаких плеч $\times 5$ или $\times 10$.
  * Перед длительными праздниками и выходными связки со скромным фандингом закрываются в пятницу вечером.

#### Особенность 2: Тонкий стакан UTEX и сокрытие L2 глубины
* UTEX не транслирует глубокую книгу ордеров (виден только лучший Bid и Ask).
* Крупный маркет-ордер ($\ge \$30\,000$) на тонком газе `GASM` пробьет стакан и приведет к проскальзыванию в $1\dots 3\%$.
* **Правило исполнения**:
  * Вход строго **лесенкой** (пакеты по $\$5\,000 \dots \$20\,000$ с интервалом в 2–5 минут).
  * Выставление лимитных ордеров внутрь спреда на UTEX. При наливке — моментальный добор второй ноги на Binance.

#### Особенность 3: Асимметрия структуры овернайтов (Ключевое отличие!)
* **CME Фьючерсы (`GASM`, `CL`)**:
  * Овернайт: $0.0194\%$ в день ($\approx 7\%$ годовых) начисляется на **полный ноционал позиции**.
  * Окупаемость: газ `NATGAS` на Binance имеет выплаты **каждые 4 часа (6 раз в день!)**. При ставках $0.15\dots 0.40\%$ за 4ч дневной фандинг составляет $+0.9\dots +2.4\%$, кратно перекрывая суточный овернайт $0.0194\%$.
* **Акции США (`NOK`, `AXTI`, `MSTR`)**:
  * Овернайт на UTEX списывается **ТОЛЬКО С ЗАЁМНЫХ СРЕДСТВ** ($0.0278\%$/день).
  * **При торговле 1:1 без плеча заёмных средств нет $\implies$ овернайт РАВЕН $0.00$!**
  * Текущих расходов на удержание нет вообще. Единственный расход — разовая комиссия за оборот ($\approx 0.2\%$). Весь фандинг оседает в чистую прибыль.

#### Особенность 4: Внутридневной скальпинг «Раздвижки спреда» (Фирменный сетап Антона)
* Между интервалами списания фандинга (за 4–8 часов) относительный спред цен между перпом Binance и спотом UTEX колеблется под воздействием локальной ликвидности.
* Если перп Binance резко оторвался вверх на $+0.8\dots +1.5\%$, открывается связка.
* При возврате спреда к паритету (через 1–2 часа) связка закрывается досрочно с фиксацией прибыли со спреда, даже не дожидаясь отсечки фандинга!
* **Кейс Антона**: $+\$40$ USDT чистыми на капитале $\$1\,500$ всего за пару часов ($+2.66\%$ за сделку, $+973\%$ годовых).

## 6. Архитектура реализации в кодовой базе `CryptoArbitrage`

Для исключения захламления и поддержания чистоты кода система делится на модульный пакет:

```
D:\GitHub\CryptoArbitrage\cryptoarb\strategies\
├── funding\
│   ├── __init__.py           # Единая точка экспорта стратегий
│   ├── common.py             # Базовые протоколы: TwoLegSyncProtocol, LegFailureHandler, NotionalCalculator
│   ├── crypto_funding.py     # Под-проект 1: Межбиржевой крипто-фандинг (24/7, CEX-CEX)
│   └── utex_funding.py       # Под-проект 2: TradFi-фандинг (UTEX CME/Equities vs Binance/Bitget)
├── funding.py                # Обратно-совместимый фасад для Engine и Dashboard
```

### 6.1. Модуль `common.py` (Общий фундамент)
* Класс `TwoLegSyncProtocol`:
  * Метод `execute_two_phase_entry(leg_primary, leg_hedge, slippage_cap)`
  * Метод `execute_two_phase_exit(leg_primary, leg_hedge)`
* Класс `LegFailureHandler`:
  * Метод `handle_partial_fill(primary_fill, hedge_fill) -> Action`
  * Метод `emergency_unwind(filled_leg) -> Result`
* Модель `DeltaNeutralPair`:
  * Поля: `symbol_primary`, `symbol_hedge`, `notional_usd`, `current_delta`, `entry_spread_pct`, `funding_accrued`.

### 6.2. Модуль `crypto_funding.py` (Под-проект 1)
* Класс `CryptoFundingStrategy`:
  * Сканирование кросс-пар между криптобиржами (`quotes.items()`).
  * Фильтрация по порогу $\Delta\text{Rate} \ge 0.08\%$ за 8ч.
  * Контроль горизонта 72ч, инверсии ставок и стоп-лосса по расхождению цен.

### 6.3. Модуль `utex_funding.py` (Под-проект 2)
* Класс `UTexFundingStrategy`:
  * Спецификация инструментов TradFi (`NATGAS`, `CL`, `NOK`, `AXTI`).
  * Мониторинг часов работы сессий (NYSE / CME).
  * Учет овернайта: $0.0\%$ для акций при 1:1, $0.0194\%$ для фьючерсов.
  * Детектор 4-часовых и 8-часовых интервалов.
  * Детектор «Раздвижки спреда» (Basis Scalping): фиксация прибыли при внутридневном схождении базиса до часа выплат фандинга.
